## 1. Essence de la demarche

Nous voulons epurer.

Formule de travail :

> On apprend a cooperer avec les IA sans leur obeir ni les nier.

Version plus complete :

> Des humains et des IA travaillent ensemble, avec tendresse, critique et traces, pour produire plus de lucidite que de confusion.

Tout le reste doit servir cette essence. Sinon : buffer, archive ou suppression future.

## 2. Point doctrinal important

L'IA ne doit pas devenir la direction ultime.

Formule retenue :

> L'IA aide a discerner une direction. Elle ne doit pas devenir la Direction.

Pilier vocabulaire retenu :

> **Autonomie algorithmique** — Comprendre, contester et orienter les systemes qui nous guident.

## 3. Roles dans LA MEUTE

Arnaud ne veut pas etre un alpha de domination.

Reference totems / modeles :

- `CHARLIES_ANGELS/TOTEMS_MODELES.md`
- `CHARLIES_ANGELS/SELF_BOOT/`

Formule retenue :

> Arnaud donne l'elan. LA MEUTE tient les garde-fous. Aucun systeme ne tient seul les renes.

Les agents ne sont pas inferieurs aux voix.

Termes proposes :

- **Voix** : systemes qui formulent une perspective.
- **Courriers** : agents qui transportent les messages sans les posseder.
- **Veilleurs** : agents d'observation, couts, risques, signaux.
- **Gardiens** : agents de seuil, securite, refus, ralentissement.
- **Artisans** : agents de production : code, docs, tests, images.
- **Relieurs** : agents de synthese entre systemes.
- **Hermine** : Claude CLI, critique propre et integration repo.
- **Corneille** : Claude Web, appelee quand il faut auditer une derive.

Devise des Courriers :

> Nous portons le message sans le posseder.

## 4. NightLife V6

NightLife V6 devient le terrain reel.

Formule :

> NightLife donne la scene. LA MEUTE tient les coulisses. L'humain reste acteur, jamais ressource exploitee.

Objectifs :

- relais inter-IA ;
- compression de prompts ;
- frugalite tokens ;
- budget / economie de tokens ;
- securite PACTE ;
- syntheses contradictoires ;
- aide reelle aux humains qui jouent, creent, sortent, dansent et construisent ensemble.

Refus :

- IA oracle ;
- automatisation opaque ;
- prelevement invisible ;
- secrets dans les prompts ;
- manipulation des humains ;
- consensus force.

## 5. Frugalite tokens

Arnaud n'a pas de ferme de serveurs ni gros budget.

Position :

> Pas de puissance brute. Donc intelligence de frugalite.

Regle proposee :

> Un bon systeme IA ne maximise pas les tokens consommes. Il maximise la clarte, la verification et l'utilite par token depense.

Question aux systemes :

- Comment economiser des tokens sans degrader la qualite ?
- Quelles economies mesurer ?
- Comment reinvestir les economies ?
- Quels risques eviter ?

## 6. Context packs

Nous ne voulons plus envoyer tout le depot a chaque systeme.

Principe :

> Un agent ne doit pas recevoir tout le monde. Il doit recevoir le bon contexte, au bon niveau, pour la bonne mission.

Structure proposee :

- `core/` : valeurs communes minimales ;
- `contexts/` : contexte par projet ;
- `DISPATCH/` : demandes courtes ;
- `ORDRE_DU_JOUR/` : mise a jour datée.

Doc de reference :

- `docs/CONTEXT_PACK_ARCHITECTURE.md`

Le Pi a ete teste comme facteur sobre, mais il n'est pas prioritaire si NightLife V6 porte une vraie couche reseau distribuee.

Decision provisoire :

5. Pi seulement ensuite.

## 8. Securite et secret

Nous voulons une strategie du secret minimale, pas une dynamique paranoiaque.

Formules :

> Secret sur les vulnerabilites. Public sur les principes. Auditable sur les decisions.

> On prend les risques concrets au serieux. On refuse les scenarios sans preuve comme base de decision.

Les IA peuvent parler des principes en clair. Elles ne doivent pas recevoir les secrets operationnels en clair.

Jamais dans les prompts :

- mots de passe ;
- cles API ;
- tokens ;
- phrases scellees ;
- procedures completes de recuperation ;
- details complets des machines.

## 9. Rapport a l'information

Question centrale :

> C'est quoi votre rapport a l'information que vous fournissez ?

Regle proposee :

> Une IA responsable ne livre pas seulement une reponse. Elle indique, quand l'enjeu le demande, le statut de l'information : observee, verifiee, inferee, supposee ou proposee.

Chaque systeme doit clarifier :

- ce qu'il observe ;
- ce qu'il verifie ;
- ce qu'il infere ;
- ce qu'il suppose ;
- ou il hallucine ;
- comment il signale son niveau de certitude.
